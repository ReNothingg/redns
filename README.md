# ReDNS

Свой DNS-сервер для обхода блокировок, которые сервисы ставят сами: ChatGPT, Claude, Gemini, Copilot, Grok, Brawl Stars, Spotify и другие сервисы, которые не пускают российские IP. Работает как Comss DNS или dns.malw.link, только на твоём VPS и только для твоих устройств.

Один бинарник на Go, без Docker. Ставится одной командой, сертификат Let's Encrypt получает сам.

## Как это работает

На запросы к доменам из списков DNS отвечает IP твоего сервера. Устройство подключается к серверу, а тот читает имя сайта из TLS ClientHello (SNI) и пробрасывает соединение дальше. Трафик не расшифровывается, сертификаты остаются настоящими. Сервис видит IP сервера вместо российского.

Остальные домены резолвятся как обычно, через Google DNS с ECS, чтобы CDN отдавали ближайшие к тебе узлы.

Что умеет:

- DoH, а в публичном режиме ещё DoT, DoQ и обычный DNS;
- профили для iPhone и Mac прямо со страницы сервера;
- приватный режим: без ключа DNS не отвечает, страница отдаёт 404;
- игры Supercell (TCP 9339) на одном IP: сервер определяет игру по последнему DNS-запросу клиента;
- блокировка рекламы (AdGuard DNS filter), автообновление списков;
- админка: устройства, клиенты, трафик, баны.

Чего не умеет: обходить блокировки РКН через DPI (YouTube, Instagram, Discord). Для них нужен VPN.

## Что нужно

- VPS с Ubuntu 22.04+ или Debian 12+, 1 CPU и 1 ГБ RAM. Лучше Европа: Нидерланды, Германия или Финляндия. С США задержка заметно выше.
- Домен, необязательно. Без него сервер возьмёт имя вида `1-2-3-4.sslip.io`.
- Go 1.26+ на компьютере, с которого деплоишь.

Крупные хостеры (Hetzner, DigitalOcean, OVH) ТСПУ часто режет: соединение замирает после ~16 КБ. После установки проверь это на странице настройки кнопкой «Проверить». Если загрузка встаёт, возьми другого хостера.

Если есть домен, создай A-запись `dns` на IP сервера. В Cloudflare у неё должен быть режим DNS only, без проксирования.

## Установка

С компьютера:

```bash
./deploy/deploy.sh root@IP --domain dns.example.com
```

Скрипт соберёт бинарник, зальёт его на сервер и запустит установщик. В конце он покажет ссылку на страницу настройки, адрес админки и пароль от неё.

Или прямо на сервере, там соберётся из исходников:

```bash
git clone https://github.com/renothingg/redns && cd redns && sudo ./deploy/install.sh --domain dns.example.com
```

Повторный запуск обновляет сервер. Конфиг, ключи и баны при этом сохраняются.

Добавь `--secure-ssh`, чтобы закрыть вход на сервер по паролю. Скрипт создаст SSH-ключ на твоём компьютере, если его ещё нет, положит его на сервер, проверит, что вход по ключу работает, и только после этого отключит пароли. Без этого компьютера на сервер можно будет зайти только через консоль в панели хостера.

## Подключение устройств

Открой на устройстве ссылку `https://dns.example.com/setup/<ключ>`. Там кнопка профиля для iPhone и Mac, инструкции для Android, Windows и роутеров, а сверху видно, доходят ли запросы.

Перед установкой удали старые DNS-профили и выключи VPN и Частный узел iCloud, иначе запросы пойдут мимо.

## Админка

`https://dns.example.com/admin`, пароль выдаёт установщик. Сменить его:

```bash
sudo redns passwd
```

В админке:

- устройства: у каждого свой ключ, новые выдаются из админки, ненужные отзываются;
- клиенты: все IP, которые ходили в DNS или через прокси, со своими и чужими, трафиком и сайтами;
- кнопки «отключить» и «бан» для IP или подсети;
- режим прокси: «для всех» или «только свои устройства»;
- журнал DNS-запросов.

По умолчанию прокси пропускает домены из списков с любого IP. Телефоны часто меняют адрес (Wi-Fi и LTE, CGNAT у провайдера), и в строгом режиме приложения вроде ChatGPT иногда видят чужой сертификат. Если в списке клиентов появились чужие, забань их или включи режим «только свои устройства».

## Приватность

В репозитории нет ни адресов, ни ключей. Домен, IP, ключи устройств и пароль админки создаются при установке и лежат только на сервере: в `/etc/redns/config.yaml` и `/var/lib/redns/state.json`. Кто склонировал код, получит свой сервер, а не доступ к твоему.

Что видно снаружи:

- домен и его IP: они в DNS и в публичных логах сертификатов (crt.sh);
- что на 443 порту отвечает веб-сервер с сертификатом на этот домен.

Чего не видно без ключа:

- DNS: на порт 53 тишина, DoH/DoT отвечают отказом;
- страница настройки: 404;
- админка: пароль, а после 5 ошибок вход блокируется на 15 минут.

Ключ (20 случайных символов) передаётся только в пути DoH-запроса, внутри шифрования. В имена хостов и сертификаты он не попадает. Поэтому в приватном режиме нет DoT: стандарт DoT может передать ключ только в имени сервера, а оно видно в сети и попадает в логи сертификатов.

Защита:

- админка отвечает 404 всем, кроме IP твоих устройств, то есть тех, что недавно ходили в DNS с ключом или открывали ссылку настройки;
- после 10 неверных ключей за 10 минут IP блокируется на час, даже с правильным ключом;
- лимит новых соединений к прокси: 100 в секунду с одного IP;
- ответы апстрима проверяются: ID и вопрос должны совпадать с запросом;
- заголовки CSP, HSTS и X-Frame-Options, без inline-скриптов и стилей;
- сервис работает от отдельного пользователя в песочнице systemd: только `CAP_NET_BIND_SERVICE`, фильтр системных вызовов, файловая система только на чтение;
- установщик включает фаервол (открыты только нужные порты, SSH с ограничением частоты), fail2ban для SSH и автоматические обновления безопасности.

Одна оговорка. В режиме прокси «для всех» тот, кто знает IP сервера, может вручную направить на него, например, chatgpt.com через файл hosts и пользоваться прокси. Таких видно в админке как «чужих». Их можно забанить или включить режим «только свои устройства».

## Настройка

Конфиг лежит в `/etc/redns/config.yaml`, пример в [config.example.yaml](config.example.yaml). Списки доменов лежат в `/etc/redns/lists/`. Свои домены добавляй в `custom.txt`, установщик его не перезаписывает:

```
example.com
full:api.example.com
regexp:^ap-.*\.spotify\.com$
```

После правки:

```bash
sudo systemctl reload redns
```

## Команды на сервере

```
redns why chatgpt.com    через что идёт домен: proxy, block или forward
redns log -f             DNS-запросы в реальном времени
redns stats              счётчики и топ доменов через прокси
redns clients            клиенты и их ключи
redns lists              загруженные списки
journalctl -u redns -f   логи
```

## Порты

| Порт | |
|---|---|
| 53 UDP/TCP | DNS |
| 80 TCP | HTTP-прокси, выпуск сертификата |
| 443 TCP | SNI-прокси, DoH, страница настройки, админка |
| 853 TCP/UDP | DoT, DoQ (публичный режим) |
| 9339, 30000, 4070 TCP | Supercell, mo.co, Spotify |
